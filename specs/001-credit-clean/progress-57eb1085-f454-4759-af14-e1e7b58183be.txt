## Codebase Patterns
- Repository root: /Users/rodrigo.borcat/Documents/github/bootcamp-team-marsala
- Feature spec lives in specs/001-credit-clean/
- Fixture data: fixtures/lcm-users.json (10 merchants, only first 5 have merchant_id)
- prototype/ goes in specs/001-credit-clean/prototype/
- Plan says Vite 6 + React 19 + TypeScript 5 + Tailwind CSS 4 + React Router 7
- Tailwind CSS 4 uses CSS-first config (`@import 'tailwindcss'` + `@theme {}`), NO tailwind.config.ts needed
- Vite 6 uses `@tailwindcss/vite` plugin for Tailwind 4 integration
- Path aliases: `@/` -> `src/` configured in both vite.config.ts (resolve.alias) and tsconfig.app.json (compilerOptions.paths)
- Viewport: 390x844 mobile-first. `max-w-[390px]` on the main container in App.tsx
- Tests/acceptance directory is at prototype/tests/acceptance/ (not at repo root)
- Base build command: `cd prototype && npm run build`
- Base typecheck: `cd prototype && npx tsc -b`
- Base dev server: `cd prototype && npm run dev`
- `.gitignore` already covers `node_modules/` and `dist/` from Vite scaffold
- Empty directories use `.gitkeep` placeholders
- Type-level tests: for stories where there's no runtime behavior (types, data), write compile-time validation files in src/ that exercise the types structurally; tsc -b validates them
- TypeScript strict mode with noUnusedLocals/noUnusedParameters: use `void [expr1, expr2, ...]` to suppress unused-variable errors in test files
- tsconfig.app.json includes "src" — test files that need compilation go there; acceptance specs go in tests/acceptance/
- Importing JSON fixtures from the monorepo root (prototype → src → data): path is `../../../../../fixtures/lcm-users.json`. Import JSON with `import data from 'path' with { type: 'json' }` for type-safety + tree-shaking. JSON import must be Vite/TS 5.8+ compatible with `resolveJsonModule` (default in bundler mode).
- Foreign key linking between merchants and credit data: use `merchant_id` (UUID string) as the join key, NOT `frn_id` (numeric). All CreditContract/RenegotiationPlan/DebtSummary reference `merchantId` (UUID string). The `activeMerchants` filter uses `merchant_id !== null` to select the 5 fixture merchants.
- JSX must be in `.tsx` files. `.ts` files with JSX cause parse errors even with `"jsx": "react-jsx"` in tsconfig.
- iFood brand tokens defined in index.css via `@theme`: --color-ifood-red (#ea1d2c), --color-ifood-red-dark (#c4162a)
- All UI components use Tailwind classes exclusively, no CSS modules or styled-components.
- Format functions use Intl.NumberFormat/Intl.DateTimeFormat with 'pt-BR' locale for proper Brazilian formatting.
- AppContext uses useReducer for state management; hooks use a private useAppContext() that throws if used outside Provider. Data is loaded synchronously from static imports — no async data fetching needed for the prototype.
- Context hooks pattern: useMerchant, useDebtSummary, usePlans, useSelectedPlan, useContract are all selector hooks that derive data from the current AppState by joining on selectedMerchantId/selectedPlanId.
- Page components follow a consistent pattern: import PageShell, use context hooks (useMerchant, useDebtSummary, etc.), guard against missing data, render UI with Tailwind, wire navigation via useNavigate. Each page is registered as a route in App.tsx.
- LCM trending item format: `"Item Name (share X% -> Y%)"`. parseTrendingItem uses regex to extract name and share values, then formats with pt-BR decimal separator.
- LCM top_popular_items are raw strings (e.g. "Acai de 700ml (99 orders)") — rendered directly without parsing.
- PlanCard component pattern: rounded-xl border card with installment count header, monthly amount in ifood-red, total cost, first payment date with calendar icon, and full-width primary button. The onSelect callback receives the full RenegotiationPlan object and is wired to context dispatch + navigation in the parent page.
